## Варіант

Предметна область – за номером у журналі групи (таблиця А.1 посібника). Індивідуальне правило валідації –
№ (S mod 8) + 1 з таблиці А.2, де S – сума номерів літер прізвища латиницею (A = 1 … Z = 26, як у закордонному паспорті).
Порахувати можна вручну або командою з кореня репозиторію (один раз на початку ПЗ 1):

```
node tools/variant.mjs PETRENKO --number 7 --write
```

Команда показує правило і записує `app/entity.json` (поля предметної області), `app/variant.json`
і перший запис `app/data/items.json` з вашим прізвищем у назві.

- S = [___], індивідуальне правило № [_]: [текст правила]

## Запуск (усі команди – з кореня репозиторію)

```
npm install
npm test            # автоматизовані тести app/ (ПЗ 1)
npm run dev         # сторінка app/: http://localhost:5180 (ПЗ 2)
npm run mock        # mock-сервер API: http://localhost:3000/api/items (ПЗ 3)
npm run typecheck   # перевірка типів (ПЗ 3)
npm run server      # власний сервер API (ПЗ 4–5): http://localhost:3000, документація /docs
npm run contract    # контрактні тести (ПЗ 4); з ПЗ 5 – npm run contract -- --auth
npm run client      # клієнт React (ПЗ 6): http://localhost:5185
docker compose up --build   # застосунок у контейнерах (ПЗ 6): http://localhost:8080
```

Сторінка з даними на сервері: http://localhost:5180/?api=http://localhost:3000.
Mock-сервер з імітацією збоїв і довшою затримкою: `npm run mock -- --fail-rate 0.3 --delay 1000`
(типово затримка 300 мс, збоїв немає). Зразок «Бібліотека» запускається поруч: `npm run demo:dev`, `npm run demo:mock`.

Кожен рівень містить вимоги попереднього (табл. 2.3, 3.3, 3.4 посібника).
